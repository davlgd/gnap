GNAP delegation lab

A client asks for read-only access to a synthetic folder and archive using resource-set references registered by the RS at startup. You play the resource owner, then change or revoke the ongoing grant. References name rights; they do not grant access.

Public sandbox, synthetic data only. This demonstrates a restricted GNAP HTTPSig profile, not complete protocol coverage or certification. Client and AS run in one deployment but exchange real signed HTTP requests.

3. Change or revoke the grant

Live token rights: None. Live tokens by label: None.

You can cancel a pending request or revoke an approved grant while continuation remains open, after the AS wait period. Changing rights requires an approved grant: a reduction within live rights is approved directly, while expansion needs fresh consent. Previous tokens remain usable while that consent is pending; approval replaces them all. Denial closes continuation but does not revoke those earlier tokens.

4. Read resources and manage a token

Token values and private keys are intentionally never exposed in this page. A two-token request asks for one consent covering a documents token and a reports token; the owner may allow only the reports token. Each token has its own rights, resource server and management: rotating or revoking one leaves the other in place, and neither works at the other's resource. The metadata action lets the folder RS obtain a separate token for a second RS: one metadata read right, bound to the first RS's key, valid for at most 60 seconds. It does not grant archive document access. The folder RS attempts revocation after the call; an inconclusive reply gives 503, without proving whether deletion happened.

Each RS discovers the configured AS and authenticates introspection with its own key (RFC 9767). It then checks the caller's signature, exact resource right and expiration locally. No positive decision is cached. An unavailable exchange refuses access temporarily (503), distinct from a refused token context or proof (401). Parent token lifetimes and browser sessions are limited to 20 minutes. All roles run in this one teaching application.
