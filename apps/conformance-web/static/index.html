Inspect a captured message

Core GNAP messages go through the SDK's own validators. AS discovery and RFC 9767 messages get separate HTTP and JSON assertions on shared registry data, and the optional digest check uses gnap-crypto. None of these is a complete independent implementation.

Use test data only. Don't paste production tokens, private keys, personal data, or whole authenticated traces. Imports reach this server over HTTPS when it is deployed; it neither stores nor logs them, though its hosting is outside that promise, and your browser may keep form contents.

Select the message actually captured. Request and response checks are distinct.

Missing context isn't tested, and optional capability lists may be omitted. HTTP on loopback is a development deviation, not a conformant discovery endpoint.

Optional caller-declared comparison context

This is your declaration, not verified network or token evidence. No URL is fetched. Leave it blank when unknown: context can't override a contradiction in the message.

Derivation imports inspect selected grant-message fields only: they don't prove the parent token's validity, RS1's authentication, downstream rights, audience, or revocation. Continuation, interaction and error responses aren't observations of a successful issuance. The token-label pair is a local {"request":{...},"response":{...}} object, not a GNAP wire message.

Probe an approved endpoint

Only the exact endpoints this service's operator approved are offered, and you can't supply another URL. A probe sends either a malformed grant to an AS, an unauthenticated GET to an RS, or one OPTIONS discovery request to an AS, without redirects or credentials. A refusal doesn't prove that a grant works, and a discovery document doesn't prove its capabilities.

    Run the same checks from a terminal

    The gnap-conformance command prints the same findings as text or JSON, and its exit code tells failed (1) from inconclusive (2). It reaches the server you name, which makes it the tool for your own authorization server and for CI.

    cargo run --manifest-path apps/conformance-web/Cargo.toml --bin gnap-conformance -- \
  discover https://as.example/gnap
    gnap-conformance probe https://as.example/gnap --json
    gnap-conformance lifecycle https://as.example/gnap --proof jwsd --alg EdDSA --access read

    The workbench guide lists every option and what each command sends.

    What these checks don't establish

    Imports and unsigned probes don't verify signatures, replay protection, consent, a token's lifecycle, authenticated introspection, or effective rights. The signed lifecycle exercises selected outcomes on a synthetic resource after your consent; it reuses the client SDK and doesn't certify an AS, an RS, or a client.

    AS discovery checks the document, not the advertised features. RFC 9767 imports inspect message shapes and the comparisons you declare: an imported active: true doesn't prove that a token is active, and a resource registration doesn't prove that a reference resolves. Absent optional fields and unknown registry names are reported as not tested, each with its own explanation. No imported URL is fetched, and probes check TLS certificate validation only, not a TLS audit.

    References: RFC 9635, RFC 9767, the IANA GNAP registries, and the IANA Subject Identifier Formats.
