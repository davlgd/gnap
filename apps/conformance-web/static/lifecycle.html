This workbench uses its own test-client key. You decide on the authorization server's page whether it may read a synthetic resource. After approval, it tests successful access, replay rejection, a different signing key, rotation and revocation. Denial tests only the refusal path.

No production data or private key input. Only operator-approved targets are offered. A report describes this bounded scenario, not complete GNAP conformance or an independent protocol implementation. The client SDK supplies messages and finish verification; the HTTP/JSON outcome checks are separate.

The operator must approve the workbench's current public key at the AS. It changes on restart; access remains refused until the new key is approved. No key is approved automatically.
