Run a signed grant from request to revocation

The workbench requests access to a synthetic resource with its own key, and you decide at the authorization server. After an approval, it reads the resource, then checks replay rejection, a foreign key, rotation, and revocation. A denial checks the refusal path only.

Start a run

The operator has to approve the workbench's current public key at the authorization server first. The key changes on every restart, and nothing approves it automatically. Only operator-approved targets are offered, and no production data or private key is ever asked for.

Observed checks

These checks describe this bounded run, not GNAP conformance as a whole. The client SDK builds the messages and verifies the finish; the HTTP and JSON outcome checks are separate from it.

Limits of a run

One run starts every 60 seconds, shared with the probes, with at most four running and eight reports kept. Consent and network work expire after five minutes, and reports after ten. Closing this page doesn't cancel a run you already authorized. Network failures leave a check inconclusive, and cleanup can't be guaranteed during an outage.
